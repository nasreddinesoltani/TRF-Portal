# Top-3 Podiums by Category — Rankings Page Feature

## Summary
Add a view toggle to the Competition Rankings page (`/competitions/:id/rankings`): **"Full Rankings"** (current tables) vs **"Top 3 Podiums"** (new). The podiums view groups the competition's events by category and shows each event's Final A podium — 1st/2nd/3rd with athlete/crew name, club/nation, and time. Data is computed live from completed races (works before results are published), reusing the same Final-A and masters-filter logic as the existing ranking engine.

## Backend

**1. `backend/Services/rankingService.js` — new exported `buildCompetitionPodiums(competitionId, options)`**
- Load competition + completed races (`status: "completed"`, populated: category, boatClass, lanes.club, lanes.athlete, lanes.crew, `lean()`), same as `buildCompetitionRanking` does.
- Masters filter: when `options.includeMasters === false`, reuse the exact same masters detection already in the service (minAge >= 27, "MAS"/"VET" abbreviations, "MASTER"/"VETERAN" titles).
- Decisive-race selection, mirroring the service's `journeyMode: "final_only"` fallback: group races by `journeyIndex`; within a journey that has phase labels keep only `isFinalARace` races (`/^final(\s+a)?$/i`); for journeys without phase labels (legacy), keep all its races.
- Per podium race: consider only lanes with `result.status === "ok"` (hors_course/DSQ/DNS/DNF excluded), sort by `elapsedMs` asc → `finishPosition` asc → lane, take top 3.
- Response shape (reuses the page's `buildGroupTitle` conventions):
```js
{
  competition: {_id, code, names},
  stages: [{index, name, date}],           // journey names for labels
  groupMetadata: { [groupKey]: {gender, categoryAbbr, categoryNames, categoryId} },
  categories: [{
    groupKey,                               // category abbreviation
    events: [{
      eventKey, journeyIndex, phase, eventNumber, raceId,
      boatClass: {_id, code, names, crewSize, weightClass},
      podium: [{ position, athleteId, name, nameAr, crewNames, clubId, clubName,
                 representingNation, representingType, elapsedMs, lane }]
    }]
  }],
  generatedAt
}
```
- Categories sorted by abbreviation; events by journeyIndex then eventNumber.

**2. `backend/Controllers/rankingController.js` — new `getCompetitionPodiums`**
- Reads `includeMasters` query param (same pattern as `getCompetitionRanking`), calls the service, returns 404 on "Competition not found", 500 otherwise.

**3. `backend/Routes/rankingRoutes.js`**
- `router.get("/competition/:competitionId/podiums", getCompetitionPodiums)` — public GET, consistent with the other ranking reads.

## Frontend — `frontend/src/pages/CompetitionRankings.jsx`

- **Toggle**: segmented control at the top of the controls card — "Full Rankings" / "Top 3 Podiums" (Tailwind, matching page styling). New state `viewMode`.
- **Conditional controls**: in podiums view hide the Ranking System select and Include Penalties (not applicable); keep Include Masters (triggers refetch).
- **Fetch**: lazy fetch of `GET /api/rankings/competition/${competitionId}/podiums?includeMasters=...` when the view is first opened or the Masters toggle changes — same Bearer token + `handleUnauthorized` + `toast.error` pattern as the existing fetches.
- **New `PodiumsView` component** (internal, like `RankingTable`): per category an amber-gradient card header (medal theme, reusing `buildGroupTitle` + `groupMetadata`) and per event a labeled section (boat class code + weight class + journey/stage name) with 3 podium rows: `PositionBadge` (reused), athlete name or joined crew names, club name (or nation label via existing `countryLabel` helpers), and time via `formatTime` from `lib/format.js` ("—" if untimed). Empty state reuses the existing 🏆 empty card. Hide `PointTableLegend` in this view.
- **PDF export**: make the header "Export PDF" button context-aware — in podiums view it exports the podiums (jsPDF + autotable, one section per category, following the existing export scaffolding).
