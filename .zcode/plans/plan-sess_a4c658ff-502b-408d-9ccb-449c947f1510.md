# Goal

Enable and verify final-journey qualification: after several preliminary journeys, the system identifies the crews qualified for the final journey per event (category + boatClass), **assigns their lanes in the final using the international seeding helper** (World Rowing chevron pattern ordered by qualification rank).

# Your rules, mapped to the design

1. **DNF backfill** — crews qualify by accumulated points; if fewer than 6 qualify, remaining slots are filled with the best DNF crews (DSQ/DNS/ABS/hors_course are never qualified).
2. **Tie at the cut expands the final** — crews tied at 6th after the full tie-break chain all qualify; the final may be played with 7+ boats. Response flags when the count exceeds the 8-lane limit.
3. **Points accumulated over journeys, per crew slot** — points go to the crew slot (**ASL1**, **EPT2** = club + crewNumber), not to individual athletes, so athlete changes between journeys don't split the crew. Reuses the existing `entityType: "crew"` convention and crew-slot keying (`rankingService.js:964-1017`).
4. **Lane assignment (new)** — after selection, crews are ordered by qualification rank and assigned lanes with the chevron helper used by international seeding (`getLaneNumbers` / `LANE_PATTERN [3,4,2,5,1,6,7,8]`, `competitionRaceController.js:39-44`): rank 1 → lane 3, rank 2 → lane 4, rank 3 → lane 2… Each qualified crew also carries `seed = qualification rank`, so any later regeneration via the existing "seeded" strategy reproduces the same order.

# Qualification algorithm (per category + boatClass)

1. Determine the final journey like `rankingService.js:358-390`: stage flagged `isFinalDay`, else highest `journeyIndex`.
2. Pool = completed races with `journeyIndex < finalJourney` (final-journey races and `Final`/`Final A/B/C` phases never feed qualification).
3. Per race, compute lane points with the existing `calculateLanePoints` (`rankingService.js:129`) + `analyzeRaceContext` (line 188): `ok` → point-table points by `finishPosition` (default 1st=20, 2nd=12, 3rd=8…); `dnf` → position after last finisher (existing DNF rule); `dns/dsq/abs/hors_course` → 0. If `finishPosition` is missing but `elapsedMs` exists, derive it from time within the race.
4. Aggregate per crew slot (club+crewNumber; nation+crewNumber for nation entries; crew-member IDs / athlete as fallback): totalPoints, firstPlaces, secondPlaces, totalTime, per-journey breakdown.
5. Rank: totalPoints desc → more_first_places → more_second_places → total_time asc → alphabetical (same chain as default `tieBreakers`, `rankingSystemModel.js:226-234`).
6. Cut: top 6 (`topN`); crews tied with the last qualifying slot are all included (rule 2). If fewer than 6 crews have qualifying results, DNF crews backfill remaining slots (rule 1).
7. Lane assignment (rule 4): chevron lanes by qualification rank, capped at 8 lanes; `exceedsLaneLimit` flag if more than 8 boats qualify.
